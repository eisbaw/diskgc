From task-5 (deletion engine): delete inside each locked profile directory by running engine::walk + engine::delete per entry (a Candidate is an open parent fd, its mount id and the entry's path): .fingerprint/ first, then every other entry except the lock files (never make a lock file a candidate). The recogniser only looks inside a candidate, so entries of a profile directory are not contains_special. The engine stops at the first identity mismatch (End::Changed) and reports End::Failed { ENOTEMPTY } when Cargo created something after the walk; End::GateRefused is a run error. Call positions are reproducible (names sorted per directory), which race test 6's seeded kill positions can rely on.

From task-5 round 2 (deep gate): the engine now refuses (contains_special) any candidate holding an entry with a known Cargo lock name (.cargo-lock, .cargo-build-lock, .cargo-artifact-lock) anywhere, the candidate itself included, so a profile directory can never be a plain-delete candidate. This task's plan is unaffected: its candidates are the entries of a locked profile directory except the lock files (.fingerprint/, deps/, build/, incremental/, binaries), which hold no lock files in the layouts measured (Cargo 1.90 and 1.96 put them at the profile root). If one ever does, the engine refuses that entry (contains_special), which is the conservative outcome (treat as unsupported_layout here). Candidate::new now takes the parent's &Resolved plus the entry's path.

From task-6: the Cargo protocol holds the Cargo lock files, not a flock on each entry, so do not use inuse::delete_unused for the entries of a locked profile dir; use inuse::Checker::check(host, &candidate, &record) after the walk of each entry and start engine::delete before the returned Clear.fresh_until (re-check with a new scan, checker.forget(), when it passed). The Cargo-specific process heuristics (task-9) run on the same scan. A suspend between check and delete is handled by fresh_until (CLOCK_BOOTTIME).

From task-6 round 2: Checker::check now re-checks against a new scan itself when the scan is stale after the verdict; call it right before each engine::delete and start the delete at once (Clear::fresh_until is the hard limit). Build the Checker with Options::from_rules of the entry walk's Rules.

From task-6 round 3 (SUPERSEDES the two earlier task-6 notes on this task, which contradicted each other on freshness): the API is settled. Build one checker with inuse::Checker::new(&rules, inuse::REUSE_LIMIT) from the Rules of the entries' walks. For each entry of a locked profile dir: engine::walk, then checker.check(host, &candidate, &record) -> Result<Result<Clear, Skip>, HostError> (a Clear is made only there and only if its scan is fresh after the verdict; the checker itself rescans once otherwise), then inuse::delete_cleared(host, clear, &candidate, &record, options) -> Result<Deletion, Clear>, which refuses an expired Clear (Err: call checker.forget() and check again, once). Implementation (2026-10-18, implementer; staged, not committed, awaiting the deep review gate). Code: diskgc-core cargo_target/reclaim.rs (cargo_target::reclaim -> Reclaimed {removed_entries, removed_bytes, locks_held, end: ReclaimEnd}); rules in docs/safety.md, cargo-target: Reclaim protocol (rewritten), Lock files (lock order), Layouts, Eligibility walk (one budget per target).

Protocol as built:
1. Lock: judge_layout on the discovered inspection first (no lock taken for empty or unsupported_layout), reach() from the root, then per profile dir (discovery order): open once below the target (identity = discovered), take every lock file in Cargo's measured order LOCK_ORDER = .cargo-build-lock, .cargo-lock, .cargo-artifact-lock: open O_PATH below the profile dir, identity (type included) = discovered (else changed), reopen read-only through the fd with the NEW port op Host::reopen_regular (refuses anything but a regular file by fstat of the O_PATH fd before opening; never by name; LinuxHost reopens via /proc/self/fd with O_NONBLOCK|O_NOCTTY, shared helper with read_head), flock_try Exclusive; busy -> locked.
2. Recheck under the locks: inspect again + judge_inspected (same_locks vs discovery -> changed; keep marker; owners; layout); walk_entries below the dirs opened in step 1 (H6b: no second open), one entry budget for the whole target (H4, also checked after each entry walk: the engine only bounds listings, so a lone file passed with nothing left); last build newer than the caller's judged_last_build (or unknown) -> changed; judge_idle; checker.forget() then a scan made under the locks, judge_in_use (records + cargo_evidence).
3. Delete (plan()): fingerprints of EVERY profile dir first (classic: the .fingerprint entry; per-unit: every build/<pkg>/<hash>/fingerprint, split off the build/ record with the new engine API WalkRecord::split_off and deleted below its unit dir, which is opened and matched against the record), then per profile every other entry in name order, build/ then deps/ last (layout markers last: a stopped run leaves classic, per-unit or lock-files-only). Before each part: deadline, locks_unchanged (re-list the profile dir's lock files: a lock created/removed/replaced while held -> changed, H6a), then Checker::check on exactly the part's record + cargo_evidence on checker.latest(), then inuse::delete_cleared with that record (Expired: forget, check once more). Engine End -> ReclaimEnd: Changed -> Skipped(changed), Failed -> Failed (target error), GateRefused -> GateRefused (run error), DeadlinePassed -> Stopped.
4. Release: the Locked handles are dropped (closed) when protocol() returns, whatever it returns; locks_held measured from the first lock to after the return.

Engine/core API added: Host::reopen_regular (port op; ModelHost Op::ReopenRegular 'reopen_regular' + schema; Controlled wrapper op 'reopen_regular'); WalkRecord::entry_at, listing_at, split_off; ProfileDir::same_locks; eligible.rs factored into open_profile, walk_entries (+Budget), judge_inspected, judge_idle, judge_in_use, shared by eligibility and reclaim; discover::profile renamed profile_dir (pub(super)).
