From task-53 (reclaim protocol; docs/safety.md, cargo-target: Reclaim protocol). Driver: diskgc-e2e-driver [--pause-at P] [--kill-at P] cargo-reclaim [--idle-for DUR] [--after-eligibility] ROOT... runs discovery then cargo_target::reclaim on every target found; lines: 'I target <path> <profiles>' then 'I reclaimed <path> entries=N bytes=B held_us=U' | 'I skip <reason> <path> entries=N held_us=U|none -- <where>: <detail>' | 'I failed <tag> <path> entries=N -- <msg>' (counted as failure). --after-eligibility judges each target first and passes its last build (a newer one under the locks is changed). Port calls of the protocol, in order: reach (openat2/statx/read_dir), per profile dir: openat2+statx of the dir, per lock in Cargo's order (.cargo-build-lock, .cargo-lock, .cargo-artifact-lock): openat2 O_PATH, statx, reopen_regular, flock_try; then inspect, entry walks, a fresh scan (pids...), then per part read_dir+statx (lock re-listing), statx/openat2, the scan check, unlinkat. Which race test checks which step: RT1 (build holds the lock) = step 1 locked (cargo_reclaim_skips_a_target_whose_lock_is_held@* shows it for a gated build, flock-hold exclusive and --shared). RT2/RT3 (build started during deletion waits, never concurrent) = step 1 lock order + release by close (pause at unlinkat:N, start cargo build, check /proc/locks that it waits on .cargo-build-lock (1.99.1/nightly) or .cargo-lock (1.90), resume, both succeed). RT5 (new profile between discovery and locking) = step 2 judge_inspected same_locks: pause at flock_try:1 (cargo_reclaim_changed_between_discovery_and_locking@* already does it with build --release, and with an edit+rebuild under --after-eligibility). RT6 (kill during deletion) = step 3 order: seed with --kill-at unlinkat:N (positions stable for a given tree; the harness can count fingerprint objects: classic .fingerprint/, per-unit build/<pkg>/<hash>/fingerprint) - cargo_reclaim_killed_leaves_lock_files_and_a_recognisable_profile@* does 3 points on 2 profiles; RT6 should seed many. RT7 (check holding build-lock, waiting for .cargo-lock) = step 1 (first lock busy, nothing else taken). RT8 (run/test paused between compile and run) = step 2 in-use (scan under the locks) and the per-part check. RT9 = judge_layout before locking (no lock taken). H6a (lock file created mid-protocol) = step 3 locks_unchanged before each part: a 1.99.1 build on a 1.90-made target creates .cargo-build-lock and waits; measured lock order in safety.md Lock files. Limits a race test may expose: lock files re-listed per part not per unlink; make_writable off (read-only dirs from build scripts fail with EACCES after the fingerprints).

From task-53 round 2 (mped H1-H3; docs/safety.md, cargo-target: Reclaim protocol):
- H2, the invariant the protocol's safety rests on, which the race tests MUST verify on every pinned toolchain: every reclaimable lock set holds .cargo-lock, and every Cargo takes .cargo-lock before it writes into the profile directory. Container test: a target made by 1.90 (only .cargo-lock); cargo-reclaim paused at unlinkat:N (diskgc holds .cargo-lock); start a 1.99.1 (and nightly) cargo build in the project; assert from /proc/locks that it created .cargo-build-lock, holds it, and waits on .cargo-lock, and (oracle/snapshot of the profile) that it wrote nothing else; resume: diskgc stops at the next part as changed (lock re-listing), the build then succeeds. If any Cargo writes before taking .cargo-lock, the protocol is unsafe: revise safety.md (AC #3 of this task).
- H1, RT6 seeding: include kill positions inside incremental/ (half-deleted incremental state, PRD weak assumption), and a mixed target built by 1.99.1 and then the nightly (.fingerprint/, deps/ and build/<pkg>/<hash>/fingerprint in one profile; plan() now takes both kinds of fingerprints first, model-tested only).
- H3, decision recorded: diskgc never creates a missing lock file (e.g. .cargo-build-lock in a 1.90-made profile) to hold it: that would write into the target, and the .cargo-lock invariant above makes it unnecessary. If the invariant fails a race test, revisit this.
